# dsh-background-agents

> [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) के लिए इंटरैक्टिव, लंबी-सत्र वाले बैकग्राउंड एजेंट। एक टिकाऊ चाइल्ड एजेंट शुरू करें जो काम करता रहे जबकि आप बातचीत जारी रखें — उसकी प्रगति देखें, संदेशों से उसे दिशा दें और उसे रोकें, बिना अपना सत्र छोड़े।

DSH के बिल्ट-इन बैकग्राउंड *jobs* "चलाओ और भूल जाओ" वाले टूल निष्पादन हैं: आप आउटपुट पढ़ सकते हैं और उन्हें मार सकते हैं, लेकिन उनसे बात नहीं कर सकते। `dsh-background-agents` इसे आधिकारिक सबएजेंट सीम पर **पूर्ण बैकग्राउंड एजेंट सत्रों** में बदल देता है — एक कंटिन्यूएबल चाइल्ड वार्तालाप जिसे आप कभी भी संदेश भेज सकते हैं, सुधार सकते हैं और बाधित कर सकते हैं, जबकि हर टर्न के बाद इंजेक्ट की गई एक प्रगति पंक्ति आपको (और मॉडल को) अद्यतन रखती है।

## आपको क्या मिलता है

- **`background_agent`** — किसी भी सत्र से एक टिकाऊ, कंटिन्यूएबल चाइल्ड एजेंट शुरू करें। वह अपने संदर्भ में काम करता है, तुरंत एक स्थिर एजेंट आईडी लौटाता है, और उसकी बातचीत हमेशा के लिए खुली रहती है। प्रति चाइल्ड वैकल्पिक स्कोपिंग: `tool_filter` (चाइल्ड की दृष्टि से टूल हटाता है — कभी नए नहीं देता), `persona` (समर्पित सिस्टम-प्रॉम्प्ट व्यक्तित्व) और `max_depth` (डेलिगेशन गहराई सीमा); `childProvider`/`childModel` उसकी मॉडल रिक्वेस्ट रूट करते हैं।
- **`bg_message`** — उसे और काम दें, सुधार भेजें, या बसे हुए एजेंट को जगाएँ। आधिकारिक FIFO इनबॉक्स से वितरण; एजेंट का उत्तर उसका अगला टर्न होता है।
- **`bg_list`** — आपके एजेंटों की स्थिति: लेबल, मोड, गतिविधि (`running` / `idle` / `ready` / `settled` / `archived`), संदेश संख्या, अंतिम गतिविधि समय। रीस्टार्ट के बाद संग्रहीत चिल्ड्रन पुनर्प्राप्त करता है। `recursive: true` पूरे वंश वृक्ष को `parentId`/`depth` सहित सूचीबद्ध करता है।
- **`bg_result`** — चाइल्ड का नवीनतम असिस्टेंट आउटपुट टेक्स्ट, लेबल और गतिविधि पढ़ता है, सेटल्ड सूचना के सारांश से परे। बिना टेक्स्ट वाले सोच-मॉडल के अंतिम संदेश में उसके रीज़निंग ब्लॉक की ओर लौटता है, `textSource: 'reasoning'` चिह्न के साथ।
- **`bg_stop`** — वर्तमान टर्न में रुकावट का अनुरोध। भेजो और लौटो: आधिकारिक टियरडाउन काम खत्म करता है; एजेंट फिर से शुरू होने योग्य रहता है।
- **autoReport** — हर चाइल्ड टर्न के बाद एक थ्रॉटल्ड प्रगति पंक्ति आपके सत्र में इंजेक्ट होती है (मॉडल-दृश्य, प्लगइन-स्रोत)। उसका अंतिम परिणाम आधिकारिक सेटल्ड सूचना से आता है। `reportDelivery: wakeup` से हर पंक्ति पैरेंट के निष्क्रिय होने पर पैरेंट टर्न शुरू करती है।
- **निष्क्रियता संग्रह** — `idleTimeoutMinutes` से अधिक शांत एजेंट सूचना और स्टॉप अनुरोध के साथ संग्रहित होते हैं; `bg_message` उन्हें फिर जगा देता है। `autoArchive: false` से शांत निगरानी एजेंट संग्रहित होने के बजाय पार्क रहते हैं।
- **`backgroundAgents` प्रोजेक्शन** — एक सत्र-प्रोजेक्शन इकाई जो पैरेंट लॉग को डैशबोर्ड पंक्तियों (एजेंट आईडी, लेबल, गतिविधि, अंतिम संदेश सारांश, निर्माण समय) में मोड़ती है। सब कुछ टिकाऊ लॉग से फिर बनता है — कोई अलग डेटाबेस नहीं।
- **वेब UI पैनल** — वेब GUI साइडबार में "Background agents" प्रविष्टि: लाइव स्थिति, चाइल्ड सत्र में एक-क्लिक छलांग, स्टॉप बटन, आधिकारिक `subagent.prompt` RPC से नया टर्न कतारबद्ध करने वाला संदेश बटन, और केवल-पठन `subagent.history` RPC से चाइल्ड का अंतिम असिस्टेंट टेक्स्ट झाँकने वाला परिणाम बटन। कई पैरेंट के एजेंट प्रोजेक्ट करने पर पैरेंट सत्र शीर्षक पंक्तियों को स्पष्ट करते हैं।

## त्वरित शुरुआत

```sh
# harness checkout से या जहाँ भी dsh CLI हो (web या headless)
dsh plugin --profile <name> add "github:PerryLink/dsh-background-agents#v0.4.0"
```

बंडल पैच प्लगइन पंक्ति साथ लाता है, इसलिए `dsh plugin add` उसे प्रोफ़ाइल की लेयर स्टैक (`dsh.profile.bundles`) में जोड़ देता है। पिन की गई ref वाला git स्रोत बेहतर है: रिपो अपना बिल्ड आउटपुट (`lib/`) कमिट करता है, इसलिए git इंस्टॉल को बिल्ड चरण या `allowBuilds` प्रविष्टि की ज़रूरत नहीं होती। पैकेज npm पर भी प्रकाशित है — `pnpm add dsh-background-agents` वैसे ही चलता है (हर टैग पुश को CI प्रकाशित करता है)।

प्रोफ़ाइल में उतरने वाली पंक्ति (`cordis.patch.yml` में प्रति प्रोफ़ाइल `config` ओवरराइड करें):

```yaml
- insert:
    - id: background-agents
      name: dsh-background-agents
      config:
        provider: spawn        # कंटिन्यूएबल चिल्ड्रन के लिए ctx.subagents प्रदाता
```

प्लगइन को सबएजेंट रीढ़ पहले से माउंट होनी चाहिए (`@deepseek-ai/dsh-base` पर बनी हर प्रोफ़ाइल में है: `dsh-subagent`, `dsh-subagent-spawn-in-process`, `dsh-session-projection`)।

फिर किसी भी सत्र में मॉडल से कहें, या टूल सीधे बुलाएँ:

```
background_agent "रिपो में टेस्ट विफलताओं पर नज़र रखो और मुझे बताते रहो" (label: test-watch)
bg_list
bg_message <agentId> "अब स्नैपशॉट टेस्ट भी जाँचो"
bg_stop <agentId>
```

## कॉन्फ़िगरेशन

हर समायोज्य एक सत्यापित `Config` फ़ील्ड है — इसे `cordis.yml` में बदलें, कोड में कभी नहीं।

| फ़ील्ड | डिफ़ॉल्ट | अर्थ |
|---|---|---|
| `provider` | *(आवश्यक)* | कंटिन्यूएबल शुरुआत के लिए `ctx.subagents` प्रदाता नाम (`spawn`) |
| `autoReport` | `true` | हर चाइल्ड टर्न के बाद पैरेंट में एक प्रगति पंक्ति इंजेक्ट करें |
| `reportDelivery` | `quiet` | `quiet` पंक्ति को पैरेंट की अगली मॉडल रिक्वेस्ट में जोड़ता है; `wakeup` पैरेंट के निष्क्रिय होने पर पैरेंट टर्न शुरू करता है (व्यस्त होने पर कतारबद्ध) |
| `reportThrottleMs` | `15000` | एक चाइल्ड की दो प्रगति इंजेक्शनों के बीच न्यूनतम अंतराल |
| `reportSummaryMaxChars` | `300` | इंजेक्ट की गई प्रगति पंक्ति की कठोर सीमा (इलिप्सिस सहित) |
| `resultMaxChars` | `4000` | `bg_result` पाठ की कठोर सीमा (इलिप्सिस सहित, `truncated` ध्वज के साथ) |
| `maxBackgroundAgents` | `4` | प्रति पैरेंट सत्र गैर-संग्रहित एजेंटों की कठोर सीमा; बजट सत्र के **सभी** कंटिन्यूएबल प्रत्यक्ष चाइल्ड साझा करते हैं (बिल्ट-इन `subagent` टूल से शुरू हुए भी) |
| `autoArchive` | `true` | निष्क्रियता संग्रह स्विच: `false` पर सफ़ाई कभी शांत चाइल्ड संग्रहित नहीं करती (निष्क्रियता विंडो केवल पुरानी कैश प्रविष्टियों की सफ़ाई में काम आती है) |
| `idleTimeoutMinutes` | `120` | निष्क्रियता विंडो जिसके बाद शांत चाइल्ड संग्रहित और सूचित होता है (`>= 1`) |
| `idleSweepIntervalMs` | `60000` | संग्रह सफ़ाई अवधि |
| `maxLabelChars` | `120` | प्रदर्शन लेबल सीमा (इलिप्सिस सहित) |
| `childProvider` | *(विरासत)* | चाइल्ड की मॉडल रिक्वेस्ट का प्रदाता रूट |
| `childModel` | *(विरासत)* | चाइल्ड की मॉडल रिक्वेस्ट का मॉडल आईडी |
| `maxChildDepth` | *(कोई नहीं)* | शुरुआत के `max_depth` तर्क की कॉन्फ़िग सीमा |
| `allowedChildTools` | *(कोई नहीं)* | `tool_filter` नामों की श्वेतसूची; खाली/अनुपस्थित = कोई सीमा नहीं |

## यह कैसे काम करता है — और रीस्टार्ट से क्यों बचता है

सब कुछ आधिकारिक सबएजेंट सीम से चलता है: `startContinuable`, `followup`, `interrupt`, `listChildren` — प्लगइन अपना कोई लाइफसाइकिल रूटिंग नहीं करता, किसी दूसरे सत्र के `Agent` को नहीं छूता और प्रोसेस ट्री नहीं मारता (रोकना = *रुकावट का अनुरोध*; टियरडाउन कंटिन्यूएशन मैनेजर का काम है)।

प्लगइन हर तथ्य को **एक संरचित चैनल और एक मॉडल-दृश्य चैनल** से लिखता है:

- **`background-agents/fact` संरचित तथ्य घटनाएँ** (v0.3.0+) — पंजीकृत / संदेश / स्टॉप / प्रगति / संग्रहित तथ्य, पैरेंट लॉग में केवल-लॉग रिकॉर्ड के रूप में `ignorable: true` चिह्न के साथ जोड़े जाते हैं; जो पाठक यह प्रकार नहीं जानते वे लॉग अस्वीकार करने के बजाय रिकॉर्ड छोड़ देते हैं, इसलिए पुराने harness बिल्ड और पुराने प्लगइन संस्करण नए लॉग खोल लेते हैं;
- `tool/result` का **रिप्ले मेटाडेटा** — v0.3.0 से पहले के लॉग के वही तथ्य (केवल तब मोड़े जाते हैं जब पंक्ति की संरचित उत्पत्ति न हो);
- **इंजेक्ट किए गए `user/message` नोटिस** (मॉडल-दृश्य) स्रोत `{ kind: 'plugin', plugin: 'dsh-background-agents' }` के साथ — थ्रॉटल्ड प्रगति पंक्तियाँ और संग्रह नोटिस (विहित उपसर्ग `[background-agent <id>] …`);
- आधिकारिक **`subagent-settled` नोटिस** — चाइल्ड का टिकाऊ "बस गया" तथ्य।

`backgroundAgents` प्रोजेक्शन इकाई संरचित चैनल मोड़ती है और v0.3.0 से पहले के लॉग के लिए लेगसी फोल्ड रखती है (पंक्ति पहले संरचित तथ्य पर संरचित उत्पत्ति अपना लेती है, इसलिए दोहरे चैनल का लॉग कभी दो बार नहीं गिनता)। डैशबोर्ड और `bg_list` के तथ्य हर पुनः-खोलने पर बिना मानव-पठनीय नोटिस पाठ को पार्स किए फिर बनते हैं। जब सूची स्वयं उपलब्ध न हो (प्रोजेक्शन या सत्र भंडार गायब), `bg_list` एक स्पष्ट **`unrecoverable`** चिह्न लौटाता है — खाली सूची कभी नहीं गढ़ता।

## बिल्ट-इन सबएजेंट टूल से संबंध

harness कोर अपने सबएजेंट टूल लाता है (`subagent`, `send_message`, `interrupt_agent` और चाइल्ड-साइड `report` टूल)। इस प्लगइन के `bg_*` टूल उनके **सत्र-स्कोप्ड साथी** हैं; दोनों साथ माउंट हो सकते हैं:

| बिल्ट-इन टूल | यह प्लगइन | अंतर |
|---|---|---|
| `subagent` (`backgroundMode: 'continuable'`) | `background_agent` | वही `startContinuable` सीम; यह प्लगइन प्रति-चाइल्ड tool_filter/persona/max_depth सत्यापन और प्रति-सत्र सीमा जोड़ता है |
| `send_message` | `bg_message` | वही डिलीवरी अर्थ; `bg_message` इस बातचीत के बैकग्राउंड एजेंटों से बात करता है और प्रोजेक्शन तथ्य रखता है |
| `interrupt_agent` | `bg_stop` | वही रुकावट अर्थ; `bg_stop` संरचित स्टॉप तथ्य भी दर्ज करता है |
| चाइल्ड-साइड `report` टूल | autoReport | बिल्ट-इन को चाइल्ड मॉडल खुद बुलाता है; यह प्लगइन **हर चाइल्ड टर्न के बाद स्वतः** थ्रॉटल्ड प्रगति इंजेक्ट करता है |

कोर टूल में जो नहीं है: `bg_list`, `bg_result`, निष्क्रिय संग्रह और प्रति-पैरेंट मुड़ा हुआ पैनल प्रोजेक्शन।

दायरे से बाहर: निर्धारित ट्रिगरिंग (शेड्यूल सीम मौजूद है), क्रॉस-मशीन/दूरस्थ एजेंट, और आधिकारिक सबएजेंट एक्टिवेशन अनुबंध में कोई बदलाव।

## विकास

```sh
pnpm install        # केवल टूलिंग; harness पैकेज सह-चेकआउट से हल होते हैं
pnpm run typecheck  # सख्त TS, node + client प्रोग्राम
pnpm test           # 83 यूनिट + एंड-टू-एंड टेस्ट (असली सबएजेंट सीम, स्क्रिप्टेड LLM, jsdom पैनल)
pnpm run build      # lib/index.js (node आधा) + lib/client.js (वेब क्लाइंट बंडल)
pnpm run gen-aliases  # चेकआउट हिलने पर harness पैकेज पथ फिर मैप करें
```

```powershell
$env:DSH_HOME = 'D:/deepseek-harness/Project/Plugins/dsh-background-agents/dev/dsh-home'

```
