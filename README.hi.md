# dsh-background-agents

> [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) के लिए इंटरैक्टिव, लंबी-सत्र वाले बैकग्राउंड एजेंट। एक टिकाऊ चाइल्ड एजेंट शुरू करें जो काम करता रहे जबकि आप बातचीत जारी रखें — उसकी प्रगति देखें, संदेशों से उसे दिशा दें और उसे रोकें, बिना अपना सत्र छोड़े।

DSH के बिल्ट-इन बैकग्राउंड *jobs* "चलाओ और भूल जाओ" वाले टूल निष्पादन हैं: आप आउटपुट पढ़ सकते हैं और उन्हें मार सकते हैं, लेकिन उनसे बात नहीं कर सकते। `dsh-background-agents` इसे आधिकारिक सबएजेंट सीम पर **पूर्ण बैकग्राउंड एजेंट सत्रों** में बदल देता है — एक कंटिन्यूएबल चाइल्ड वार्तालाप जिसे आप कभी भी संदेश भेज सकते हैं, सुधार सकते हैं और बाधित कर सकते हैं, जबकि हर टर्न के बाद इंजेक्ट की गई एक प्रगति पंक्ति आपको (और मॉडल को) अद्यतन रखती है।

## आपको क्या मिलता है

- **`background_agent`** — किसी भी सत्र से एक टिकाऊ, कंटिन्यूएबल चाइल्ड एजेंट शुरू करें। वह अपने संदर्भ में काम करता है, तुरंत एक स्थिर एजेंट आईडी लौटाता है, और उसकी बातचीत हमेशा के लिए खुली रहती है।
- **`bg_message`** — उसे और काम दें, सुधार भेजें, या बसे हुए एजेंट को जगाएँ। आधिकारिक FIFO इनबॉक्स से वितरण; एजेंट का उत्तर उसका अगला टर्न होता है।
- **`bg_list`** — आपके एजेंटों की स्थिति: लेबल, मोड, गतिविधि (`running` / `idle` / `ready` / `settled` / `archived`), संदेश संख्या, अंतिम गतिविधि समय। रीस्टार्ट के बाद संग्रहीत चिल्ड्रन पुनर्प्राप्त करता है।
- **`bg_stop`** — वर्तमान टर्न में रुकावट का अनुरोध। भेजो और लौटो: आधिकारिक टियरडाउन काम खत्म करता है; एजेंट फिर से शुरू होने योग्य रहता है।
- **autoReport** — हर चाइल्ड टर्न के बाद एक थ्रॉटल्ड प्रगति पंक्ति आपके सत्र में इंजेक्ट होती है (मॉडल-दृश्य, प्लगइन-स्रोत)। उसका अंतिम परिणाम आधिकारिक सेटल्ड सूचना से आता है।
- **निष्क्रियता संग्रह** — `idleTimeoutMinutes` से अधिक शांत एजेंट सूचना और स्टॉप अनुरोध के साथ संग्रहित होते हैं; `bg_message` उन्हें फिर जगा देता है।
- **`backgroundAgents` प्रोजेक्शन** — एक सत्र-प्रोजेक्शन इकाई जो पैरेंट लॉग को डैशबोर्ड पंक्तियों (एजेंट आईडी, लेबल, गतिविधि, अंतिम संदेश सारांश, निर्माण समय) में मोड़ती है। सब कुछ टिकाऊ लॉग से फिर बनता है — कोई अलग डेटाबेस नहीं।
- **वेब UI पैनल** — वेब GUI साइडबार में "Background agents" प्रविष्टि: लाइव स्थिति, चाइल्ड सत्र में एक-क्लिक छलांग और स्टॉप बटन।

## त्वरित शुरुआत

```sh
# harness checkout से या जहाँ भी dsh CLI हो (web या headless)
dsh plugin --profile <name> add "github:PerryLink/dsh-background-agents#v0.1.1"
```

बंडल पैच प्लगइन पंक्ति साथ लाता है, इसलिए `dsh plugin add` उसे प्रोफ़ाइल की लेयर स्टैक (`dsh.profile.bundles`) में जोड़ देता है। पिन की गई ref वाला git स्रोत बेहतर है: रिपो अपना बिल्ड आउटपुट (`lib/`) कमिट करता है, इसलिए git इंस्टॉल को बिल्ड चरण या `allowBuilds` प्रविष्टि की ज़रूरत नहीं होती। (पैकेज npm पर प्रकाशित होने पर `pnpm add dsh-background-agents` भी चलेगा।)

प्रोफ़ाइल में उतरने वाली पंक्ति (`cordis.patch.yml` में प्रति प्रोफ़ाइल `config` ओवरराइड करें):

```yaml
- insert:
    - id: background-agents
      name: dsh-background-agents
      config:
        provider: spawn        # कंटिन्यूएबल चिल्ड्रन के लिए ctx.subagents प्रदाता
```

प्लगइन को सबएजेंट रीढ़ पहले से माउंट होनी चाहिए (`@deepseek-ai/dsh-base` पर बनी हर प्रोफ़ाइल में है: `dsh-subagent`, `dsh-subagent-spawn-in-process`, `dsh-session-projection`)।

फिर किसी भी सत्र में मॉडल से कहें, या टूल सीधे बुलाएँ:

```
background_agent "रिपो में टेस्ट विफलताओं पर नज़र रखो और मुझे बताते रहो" (label: test-watch)
bg_list
bg_message <agentId> "अब स्नैपशॉट टेस्ट भी जाँचो"
bg_stop <agentId>
```

## कॉन्फ़िगरेशन

हर समायोज्य एक सत्यापित `Config` फ़ील्ड है — इसे `cordis.yml` में बदलें, कोड में कभी नहीं।

| फ़ील्ड | डिफ़ॉल्ट | अर्थ |
|---|---|---|
| `provider` | *(आवश्यक)* | कंटिन्यूएबल शुरुआत के लिए `ctx.subagents` प्रदाता नाम (`spawn`) |
| `autoReport` | `true` | हर चाइल्ड टर्न के बाद पैरेंट में एक प्रगति पंक्ति इंजेक्ट करें |
| `reportThrottleMs` | `15000` | एक चाइल्ड की दो प्रगति इंजेक्शनों के बीच न्यूनतम अंतराल |
| `reportSummaryMaxChars` | `300` | इंजेक्ट की गई प्रगति पंक्ति की कठोर सीमा (इलिप्सिस सहित) |
| `maxBackgroundAgents` | `4` | प्रति पैरेंट सत्र गैर-संग्रहित एजेंटों की कठोर सीमा |
| `idleTimeoutMinutes` | `120` | निष्क्रियता विंडो जिसके बाद शांत चाइल्ड संग्रहित और सूचित होता है (`>= 1`) |
| `idleSweepIntervalMs` | `60000` | संग्रह सफ़ाई अवधि |
| `maxLabelChars` | `120` | प्रदर्शन लेबल सीमा (इलिप्सिस सहित) |

## यह कैसे काम करता है — और रीस्टार्ट से क्यों बचता है

सब कुछ आधिकारिक सबएजेंट सीम से चलता है: `startContinuable`, `followup`, `interrupt`, `listChildren` — प्लगइन अपना कोई लाइफसाइकिल रूटिंग नहीं करता, किसी दूसरे सत्र के `Agent` को नहीं छूता और प्रोसेस ट्री नहीं मारता (रोकना = *रुकावट का अनुरोध*; टियरडाउन कंटिन्यूएशन मैनेजर का काम है)।

प्लगइन **केवल उन्हीं चैनलों से लिखता है जिन्हें harness पहले से संग्रहीत करता है**। मौजूदा harness में प्लगइन सत्र-घटनाओं का पंजीकरण सतह नहीं है, इसलिए लॉग-घटनाएँ गढ़ने के बजाय यह तीन ज्ञात घटनाओं पर मुहर लगाता है:

- `tool/result` का **रिप्ले मेटाडेटा** — हर टूल कॉल के पंजीकरण / संदेश / स्टॉप तथ्य;
- **इंजेक्ट किए गए `user/message` नोटिस** स्रोत `{ kind: 'plugin', plugin: 'dsh-background-agents' }` के साथ — थ्रॉटल्ड प्रगति पंक्तियाँ और संग्रह नोटिस (विहित उपसर्ग `[background-agent <id>] …`);
- आधिकारिक **`subagent-settled` नोटिस** — चाइल्ड का टिकाऊ "बस गया" तथ्य।

`backgroundAgents` प्रोजेक्शन इकाई पैरेंट लॉग से ठीक इन्हीं तीन ज्ञात चैनलों को मोड़ती है, इसलिए डैशबोर्ड और `bg_list` के तथ्य हर पुनः-खोलने पर फिर बनते हैं। जब सूची स्वयं उपलब्ध न हो (प्रोजेक्शन या सत्र भंडार गायब), `bg_list` एक स्पष्ट **`unrecoverable`** चिह्न लौटाता है — खाली सूची कभी नहीं गढ़ता।

## यह प्लगइन नहीं है

| परियोजना | क्या करती है | सीमा |
|---|---|---|
| [titanwings/dsh-automation](https://github.com/titanwings/dsh-automation) | नए एजेंट सत्रों में निर्धारित कोडिंग कार्य | यह तय करती है कि कार्य **कब** चलें (शेड्यूलिंग)। यह प्लगइन एक लंबी बातचीत की **इंटरैक्टिव स्टीयरिंग** करता है — न शेड्यूल सीम, न cron। |
| [vlln/dsh-task-status](https://github.com/vlln/dsh-task-status) | बैकग्राउंड *jobs* के लिए स्टेटस बार (प्रगति + आउटपुट टेल) | यह टूल-स्तरीय काम **दिखाता** है। यह प्लगइन **एजेंट सत्र** बनाता और चलाता है; उसका पैनल एक हिस्सा है, उत्पाद नहीं। |
| [YYTbit/dsh-plugin-agent-dashboard](https://github.com/YYTbit/dsh-plugin-agent-dashboard) | मल्टी-एजेंट डैशबोर्ड स्किल | प्रदर्शन-केंद्रित। इस प्लगइन की पंक्तियाँ **कार्रवाई योग्य** हैं: चाइल्ड सत्र में जाएँ, संदेश भेजें, रोकें — आधिकारिक नियंत्रण तल से। |

दायरे से बाहर: निर्धारित ट्रिगरिंग (शेड्यूल सीम मौजूद है), क्रॉस-मशीन/दूरस्थ एजेंट, और आधिकारिक सबएजेंट एक्टिवेशन अनुबंध में कोई बदलाव।

## विकास

```sh
pnpm install        # केवल टूलिंग; harness पैकेज सह-चेकआउट से हल होते हैं
pnpm run typecheck  # सख्त TS, node + client प्रोग्राम
pnpm test           # 48 यूनिट + एंड-टू-एंड टेस्ट (असली सबएजेंट सीम, स्क्रिप्टेड LLM)
pnpm run build      # lib/index.js (node आधा) + lib/client.js (वेब क्लाइंट बंडल)
pnpm run gen-aliases  # चेकआउट हिलने पर harness पैकेज पथ फिर मैप करें
```

बिना चाबी वाला एंड-टू-एंड डेमो एक असली पैरेंट सत्र और बैकग्राउंड चाइल्ड को निर्धारित स्क्रिप्टेड LLM से चलाता है (कोई API key नहीं; `dev/` gitignored है — पथ अपने checkout के अनुसार बदलें):

```powershell
$env:DSH_HOME = 'D:/deepseek-harness/Project/Plugins/dsh-background-agents/dev/dsh-home'
pnpm dsh --profile headless --patch dev/cordis.yml "【父会话】驱动后台 agent 演示"
```
